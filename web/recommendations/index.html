How it works

Four stages, and the code behind each

This runs on every search. Each stage links to the file that implements it.

Browser A traveller opens or books a listing
POST /v1/signals
  1. 01

    Signals arrive

    A view, click, dwell or booking is posted per session and folded into a Redis hash, weighted by type. No account, no personal data, and a seven-day expiry.

    view 1 · search 2 · dwell 2 · click 3 · book 5 internal/ranking/signals.go
  2. 02

    Profile is built

    Those counters normalise into category affinities, amenity and vibe weights, and an average observed price. A session with no signals yields a zero profile, which the scorer treats as no personalization.

    cat:beach 0.71 · amen:pool 0.34 · avg €120 internal/ranking/signals.go
  3. 03

    Candidates are scored

    Search sends its candidates here. Each is scored as base relevance, personal fit, and a bounded business term, and every contribution that fires becomes a readable reason on the card.

    0.55 base + 0.30 personal + 0.15 business internal/ranking/scorer.go
  4. 04

    Search re-orders

    Ranked ids go back to search, which reassembles the page. If ranking is slow or down, search returns base relevance order and flags the response as degraded rather than failing.

    800 ms cap · degrade, never fail internal/search/service.go
ranked ids + reasons
Browser Results page, reordered, each card carrying its reason
Failure path If ranking is slow or down

Search returns base relevance order and marks the response degraded: ranking_unavailable. The traveller still gets results; nothing 500s.

Measured, not claimed

Offline evaluation

Six personas are declared in source with a stated 0–3 grading rule, then ranked by the same function production uses. The baseline is that identical function with an empty profile, which is what a first-time visitor receives. Full report and method · the harness

What is deliberately not on this page

  • Click-through and conversion rate. Both need live traffic. There is no honest way to produce them from a demo with no users, so they are absent rather than estimated.
  • RMSE, MAE and MSE. Those evaluate rating prediction. This engine ranks and never predicts a rating, so they do not apply.
  • Diversity is lower when personalized. That is the intended trade-off, not a regression: someone with a stated preference should get a concentrated page. It would only become a problem approaching zero, which would be a filter bubble.
